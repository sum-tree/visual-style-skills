# 舷窗挡板式明暗主题切换

把主题切换做成一个与产品视觉语言一致的“可拖动遮光机构”，而不是复制某个网站的图片、音效或源码。保留目标项目既有技术栈、设计令牌和主题基础设施；参考效果只用于理解交互机制，不是运行时依赖。

需要实现或修改代码时，先识别现有主题入口、SSR／预渲染方式、令牌来源、持久化键和可用测试工具。若项目已有 ThemeProvider、`data-theme`、class 或系统主题同步，接入它而不另建并行状态。需要详细状态机、计算公式或伪代码时，读取 [实现模式](references/implementation-patterns.md)。

## 必须保留的体验

- 用归一化进度 `p ∈ [0, 1]` 表示挡板位置；默认 `0` 为亮、`1` 为暗。挡板视觉位置、窗框受光和全页遮光预览都由同一进度驱动。
- 拖动期间不要逐帧替换整套主题令牌。保持当前稳定主题，在页面上方、控件下方放置 `pointer-events: none` 的全屏色幕：亮主题向暗主题移动时叠加暗色，暗主题向亮主题移动时叠加亮色。这样中间态连续，同时避免文字、图标和边框各自插值造成脏色与闪烁。
- 只在进度抵达端点并完成吸附时提交稳定主题。提交令牌后，让与新背景同色的不透明色幕淡出，遮住离散换色瞬间。端点颜色必须来自主题变量，不能在交互代码里维护另一套不一致的色值。
- 支持拖动、点击和键盘。使用 Pointer Events 与 pointer capture，限制非主按钮，设置 `touch-action: none`、`grab/grabbing`，并抑制拖动结束后误触发的 click。
- 释放时按 50% 阈值吸附；可根据最后一段速度增加轻量甩动判定，但速度不是必需功能。动画被新输入打断时，应从当前进度继续而不是跳回端点。
- 切换结果写入项目既有偏好存储，并在首次绘制前恢复，避免先亮后暗的闪屏。存储不可用时静默回退到内存状态。
- 控件应是语义化 `button` 或等价可操作元素，提供随状态变化的可访问名称与 `aria-pressed`。保留清晰焦点样式和足够触控面积；装饰层对辅助技术隐藏。
- 尊重 `prefers-reduced-motion: reduce`：取消弹簧和长缓动，直接到目标端点或使用很短的淡化；功能、键盘与持久化仍必须可用。声音和三维场景只能是可选增强，不能承担状态表达。

## 视觉构成

把控件拆成独立图层：窗外／亮面、后框、可位移遮光片、前框高光、透明命中按钮。优先使用项目已有资产；没有资产时用 CSS 圆角、渐变、阴影和裁切做原创的抽象控件。不要下载、描摹或打包参考站点的舷窗素材与音频。

遮光片沿单轴移动，并限制在窗洞裁切区域内；窗框可随 `p` 降低亮度或叠加冷灰色调，但页面色幕不应覆盖控件本身。移动端可以缩小视觉尺寸，命中区仍至少保持约 44×44 CSS px。控件放置不得遮挡核心导航或造成主题切换时的布局位移。

## 实施顺序

1. 将亮暗颜色重构为语义令牌，确认两个端点的正文、链接、表面、边框、焦点环和状态色均有明确值。
2. 先实现可访问的点击／键盘二态切换与首屏恢复，再加入连续进度、色幕和拖拽。
3. 把每帧更新限制在 transform、opacity、filter 或 CSS 自定义属性；不要在指针移动时让整页组件树重渲染或做布局测量。
4. 增加端点吸附、输入打断、持久化和 reduced-motion 分支。只有在产品明确需要时才增加惯性、音效或 WebGL 背景。
5. 用真实浏览器验证完整交互；若用户只要求审查或方案说明，不擅自改代码。

## 完成标准

- 鼠标、触摸、点击、Enter／Space 均能切换；拖到阈值两侧会吸附到正确端点。
- `p=0`、`p≈0.5`、`p=1` 三个画面连续，无白闪、脏色、控件跳位或页面滚动误触。
- 端点主题令牌正确，刷新后无主题闪屏；存储失败不导致交互报错。
- 快速反向拖动、动画中再次点击、pointer cancel、失焦或组件卸载不会留下捕获、动画帧或半透明色幕。
- reduced-motion 下没有弹簧／惯性，仍有明确状态；焦点、名称、对比度与触控区域合格。
- 桌面和窄屏均通过视觉检查；未引入参考网站的受版权保护资产、文案或音频。
